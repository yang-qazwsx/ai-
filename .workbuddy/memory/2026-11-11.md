## 排查：vectorStore.similaritySearch(...) 返回空（两个叠加原因）

- 现象：用户问 `List<Document> docs = vectorStore.similaritySearch(SearchRequest.builder().query(question).topK(3).similarityThreshold(0.7).build())` 拿到空。该行位于 `AiServiceImpl` 新加的热点缓存逻辑（第 ~106 行），后面主流程还有一次同名检索（变量名 `documents`）。
- **主因：Redis 索引里根本 0 条文档**。实测 `FT.INFO aa_rag_index` → `num_docs: 0`、`hash_indexing_failures: 16`；`FT.SEARCH aa_rag_index *` 返回 `:0`，但 `SCAN *aa_rag*` 有 16 个 ReJSON-RL key。索引定义 `ON JSON`，`$.knowledgeId` 是 **TAG** 字段，而 `initKnowledgeVector()` 写入的是 `metadata.put("knowledgeId", knowledge.getId())`（Long → JSON number）→ RediSearch 拒绝索引整条文档。
  - 可回滚实验确认：复制一份文档（knowledgeId 保持 int）→ 索引仍 0；把 `knowledgeId` 改成字符串 → 索引立刻变 1；删测试 key → 回 0。文档其余字段（content/question/answer/category/embedding 256维）都正常，维度与索引 `dim:256 COSINE` 匹配。
- **次因：`0.7` 阈值对中文 embedding-3(256维) 过高**。从现有 key 的向量实测余弦相似度：「账号问题」最高 **0.6462**（库ID 1）、「如何修改密码？」最高 **0.6488**（库ID 1），其余 0.40~0.62 —— 即使索引有数据，0.7 也会把全部结果过滤掉。
- 修复（3 处，均在 `AiServiceImpl.java`）：
  1. `metadata.put("knowledgeId", String.valueOf(knowledge.getId()))`，附注释说明 TAG 字段必须是字符串；业务层本来就用 `.toString()` 再转 Long，兼容。
  2. 热点缓存那次检索 `similarityThreshold(0.7)` → `0.5`（用户贴的那行）。
  3. 主流程 `SearchRequest` 的 `similarityThreshold(0.7)` → `0.5`，注释写明实测依据。
- 验证：`mvn -pl ruoyi-modules/ruoyi-system -am compile` → BUILD SUCCESS，94 源文件；两处实际阈值均为 0.5（残留 0.7 仅在注释）。
- **待用户操作**：Java 改动需重启服务；重启时 `initialize-schema: true` + `StartupTask` 会写入正确格式的新文档。Redis 里 16 个旧坏 key 可清理（推荐 `FT.DROPINDEX aa_rag_index` + 删除 `aa_rag_prefix*` 后重启），未擅自改动线上数据。

## 排查：热门问题缓存查询为空

- Redis 实证：`hot:question:detail` **TYPE=none（key 不存在）**；`hot:question:rank` 是 ZSet，只有一个 member `"null"` 分数 7（脏数据）。

## 修复：智能客服「点了没反应」（普通问题全部崩成"服务异常"）

- 现象：用户在 AI 智能客服整页里点快捷提问/发送，得不到正常回答——订单号直达正常，普通问题返回"非常抱歉，服务异常，请稍后再试"。
- **根因（字节码级确认）**：`AiServiceImpl.initKnowledgeVector()` 在 `StartupTask`(ApplicationRunner) 启动时运行，流程是 `checkIndexExists` → 存在则 `FT.DROPINDEX aa_rag_index DD`（连索引一起删）→ `vectorStore.add(documents)`。但反编译 `RedisVectorStore` 证实：`doAdd()` 只做 JSON.SET 写文档、**不会 FT.CREATE 建索引**；索引只在 `afterPropertiesSet()` 里建（且仅当 `initializeSchema=true`）。所以 DROP 掉索引后 add 不重建，导致 `aa_rag_index` 被永久删除，`FT._LIST` 返回空，**所有走向量检索的普通问题在 `similaritySearch` 抛 `No such index aa_rag_index`**，被 catch 成"服务异常"。订单号直达不碰向量库，故正常。
  - 之前 `initializeSchema` 改不改都不影响这个 bug：即使 `true`，afterPropertiesSet 只在 Bean 初始化时建一次索引，之后 initKnowledgeVector 又 DROP 掉且不重建。
- 修复（`AiServiceImpl.java` 1 文件）：
  - import `org.springframework.beans.factory.InitializingBean`。
  - 在 `FT.DROPINDEX` 之后、`vectorStore.add` 之前，加 `if (vectorStore instanceof InitializingBean) ((InitializingBean) vectorStore).afterPropertiesSet();` 重建索引。`afterPropertiesSet` 内部先 `ftList` 判断、索引不存在才 `ftCreate`，重复调用安全。
- **附带修复（前端必现超时）**：`request.js` 全局 axios `timeout: 10000`，但普通问题走大模型实测 17~21 秒，前端必现超时（弹"系统接口请求超时"后 catch 显示"服务暂时不可用"）。在 `ruoyi-ui/src/api/biz/chat.js` 的 `askQuestion` 与 `getChatRecords` 显式 `timeout: 60000`。
- 验证：`mvn -pl ruoyi-modules/ruoyi-system -am compile` → BUILD SUCCESS（101 源文件）；隔离端口 19201 启动后 `FT._LIST -> *1 +aa_rag_index`（索引重建成功），`订单多久发货` 走 RAG 命中 3 条知识（相似度 0.834/0.832/0.772）并由大模型润色，responseTime 21.1s，不再"服务异常"；启动日志 `知识库向量初始化完成，共写入9条数据`。验证进程已 terminate。
