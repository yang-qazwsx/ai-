## 重要结论：项目当前拉不到 Nacos 配置（框架版本问题，非 Nacos 部署问题）
- 现象：`ruoyi-gateway`/`ruoyi-auth` 启动报 `Config data resource ... dataId='ruoyi-gateway-dev.yml' does not exist`。
- 已排除因素（都实测过）：Nacos 版本 3.0.2 与 3.2.3、MySQL 与 Derby 存储、客户端快照污染（清空 `~/nacos` 无效）、md5 不一致（修完仍失败）、timeout 加大、显式 namespace=public。
- 关键证据：服务端 `config-client-request.log` 显示该 get 请求 `status: success`、`tenant: public`、md5 有值；同一 classpath 的 nacos-client 3.1.1 直接 `getConfig` 能拿到 1788 字符；SCA 的 `NacosConfigManager` 也成功。
- 另一条路线：改 bootstrap.yml 为 `file-extension + shared-configs`（去掉 `spring.config.import`）后不再报错、进程能启动，但服务端**收不到任何配置请求**（Bootstrap 机制在 Boot 4 下未生效），等于没拉到配置。
- 判定：**Spring Boot 4.0.6 + Spring Cloud Alibaba 2025.1.0.0 的 Nacos 配置加载桥接失效**。建议降到 Spring Boot 3.5.x（SCA 2025.1.0.0 面向 Boot 3.x）。
- 注：`ruoyi-system/pom.xml` 里「把 spring-cloud-starter-bootstrap 覆盖为 test scope」那套做法，是为了走纯 ConfigData 路线，但该路线在本环境不通。

## 【更正】Nacos 配置加载失败真实根因 = file.encoding=GBK（推翻上面"桥接失效"的判定）
- 真实根因：`NacosDataParserHandler.parseNacosData` 把配置字符串转字节时用 JVM 默认字符集。JDK17 在中文 Windows 下 `file.encoding=GBK`，而 Nacos 上的 yml 是 UTF-8 且含中文注释 → SnakeYAML 抛 `YAMLException: MalformedInputException: Input length = 1` → 被 `NacosConfigDataLoader.doLoad` 的 `catch (Exception)` 吞掉，统一包装成 `Config data resource 'nacos:xxx' does not exist`。**SCA 2025.1.0.0 与 Boot 4 的 ConfigData 桥接其实是正常的**，不需要降 Boot 版本。
- 定位技巧：把 `spring.config.import` 三项临时加 `optional:` 前缀 → 进程不中断，DeferredLog 才会回放被吞的堆栈（非 optional 时进程立刻退出，堆栈丢失，只剩一句 "does not exist"）。
- 修复一：本地 Nacos 切 MySQL 存储。`D:\nacos\nacos-server-3.2.3\nacos\conf\application.properties` 取消注释 `#spring.sql.init.platform=mysql`（3.x 只认这个属性；旧的 `spring.datasource.platform` 已失效，这正是之前一直是 "embedded storage" 的原因），db.* 原本已指向 `ry-config`。已备份为 `application.properties.bak-20261117`。重启后日志出现 `standalone mode with external storage`。配置在库里按 tenant `''` 和 `public` 各存一份，默认 namespace 均能命中。
- 修复二：JVM 固定 `-Dfile.encoding=UTF-8`。`ruoyi-system/pom.xml` 的 spring-boot-maven-plugin 加 `<jvmArguments>-Dfile.encoding=UTF-8</jvmArguments>`；IDEA 直接跑 main 不受 pom 影响，需在 Run Configuration 的 VM options 手动加（或设系统环境变量 `JAVA_TOOL_OPTIONS`）。
- Nacos 3.x 运维要点：v1 HTTP API `/nacos/v1/cs/configs` 已移除（404），验证配置要用 `/nacos/v3/client/cs/config?dataId=xx&groupName=DEFAULT_GROUP&namespaceId=public`；控制台在 9999，服务端 8848，gRPC 9848/9849，SDK 通道 7848。
- 验证结果：三条配置 `[Nacos Config] Load config ... success`，Druid `{dataSource-1,master} inited`，`Started RuoYiSystemApplication in 13.2s`，`GET /api/v1/book-search/status` 返回 `{enabled:true,reachable:true,docCount:4}`。
- 待办：gateway/auth/file/gen/job/monitor 六个服务的 pom 同样需要补 `-Dfile.encoding=UTF-8`，否则会报同样的 "does not exist"。
